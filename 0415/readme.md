# 🗓️ 4월 15일 학습 기록: 왜 React인가?

React를 사용하는 핵심 이유를 기술적 관점과 실무적 효율성 측면에서 정리한 문서입니다.

---

## 🏗️ 1. 레고 블록처럼 조립하는 UI (Modular Design)
React는 UI를 하나의 거대한 캔버스가 아니라, 독립적이고 재사용 가능한 **'컴포넌트(Component)'** 단위로 관리합니다.

- **부품화의 마법**: 공통적인 버튼, 입력창, 네비게이션 바를 한 번만 설계하면 프로젝트 전반에서 재사용할 수 있습니다.
- **독립적 유지보수**: 특정 UI에 문제가 생겼을 때 전체 코드를 건드릴 필요 없이, 해당 컴포넌트 파일만 수정하면 되므로 관리가 매우 직관적입니다.

## ⚡ 2. 가상 DOM: 스마트한 업데이트 전략 (Virtual DOM)
웹 성능 저하의 주된 원인인 빈번한 DOM 조작을 방지하기 위해 React는 중간에 **'가상 설계도(Virtual DOM)'**를 둡니다.

- **메모리 내 시뮬레이션**: 데이터가 변경되면 실제 화면을 즉시 바꾸는 대신, 메모리상의 가상 DOM에서 먼저 변화를 시뮬레이션합니다.
- **최소한의 타격(Diffing & Patching)**: 이전 상태와 비교하여 **실제로 바뀐 부분만** 골라 실제 DOM에 적용합니다.

## 📢 3. "무엇을"에 집중하는 선언적 UI (Declarative)
기존의 명령형 방식이 "어떻게(How)" 단계를 일일이 지시했다면, React는 상태(State)에 따른 **"결과(What)"**를 선언합니다.

- **상태의 정의**: "데이터가 A이면 이 화면, B이면 저 화면"이라고 결과값만 정의합니다.
- **예측 가능성**: 복잡한 이벤트 리스너와 DOM 조작 로직이 줄어들어 코드가 훨씬 간결해집니다.

## 🌐 4. 압도적인 생태계와 커뮤니티 (Global Ecosystem)
현업에서 React를 선택하는 가장 현실적인 이유 중 하나는 이미 검증된 방대한 인프라입니다.

- **검증된 라이브러리**: 상태 관리, 라우팅, 스타일링 등 수많은 고품질 라이브러리가 존재합니다.
- **강력한 지원**: 페이스북(Meta)이 주도하고 전 세계 개발자들이 참여하므로 문제 해결이 매우 쉽습니다.

## 🌊 5. 데이터의 엄격한 질서: 단방향 데이터 흐름 (One-way Flow)
데이터가 언제나 **'부모에서 자식으로'**만 흐르는 규칙을 가집니다.

- **추적의 용이성**: 데이터의 출처가 명확하여 디버깅 시 유리합니다.
- **디버깅의 명확성**: 앱 규모가 커져도 데이터 흐름이 꼬이지 않아 안정적인 구조를 유지합니다.
